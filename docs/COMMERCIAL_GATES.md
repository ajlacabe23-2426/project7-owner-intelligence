# Project 7 Commercial Gates

Project 7 must not be treated as commercially validated because the software works.

## Gate A — Technical demonstrability

Required:

- normalized source model
- deterministic prioritization
- evidence provenance
- brief generation
- API
- regression tests
- CI

Status: **implemented in the V1 foundation; CI verification pending/required.**

## Gate B — Problem validation

Before real integrations, establish evidence for a specific owner/operator problem:

- identifiable buyer
- recurring problem
- measurable consequence
- current workaround
- why existing dashboards/reports fail
- decision/action delayed by fragmentation
- willingness to spend time or money testing a solution

Pass condition: multiple independent operators describe materially similar pain and can provide a measurable success criterion.

## Gate C — Pilotability

Required:

- one narrow validated workflow
- minimal required source set
- source permissions defined
- baseline metric
- expected action/outcome
- safe synthetic or authorized data
- pilot scope and success criteria

## Gate D — Production capability

Required before production customer data:

- authentication
- organization/tenant isolation
- authorization
- managed persistence
- encrypted secrets
- source-level least privilege
- idempotent ingestion where relevant
- connector retries/failure handling
- structured logs and monitoring
- audit trail
- retention/deletion policy
- support/incident process

## Gate E — Commercial validation

Required:

- real operator usage
- measurable improvement or time/risk reduction
- evidence that the brief changes or accelerates a useful action
- willingness to pay
- understood implementation/support cost
- repeatable deployment pattern

## Packaging test

A candidate offer is not ready until it can answer:

> Who pays, what exact outcome they buy, what we deliver, how long setup takes, what data is required, how success is measured, what it costs to deliver, what we charge, and how customer #2 is deployed without rebuilding the product.

## Kill / reposition rule

If existing tools already solve the validated problem adequately, do not add arbitrary AI features to manufacture differentiation. Reposition the system, narrow the problem, or preserve it strictly as a career/architecture project.
